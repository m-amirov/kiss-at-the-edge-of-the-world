# State contract — Season 1, schema 4

`src/season-data.js` — исполняемый источник состояния; `content/season-1-script.md` и этот документ описывают его смысл.

| Поле | Назначение | Наблюдаемый payoff |
|---|---|---|
| `routeIntent` | Осознанная связь после эпизода 7 | Доступен только соответствующий эпизод 8 и конфликт |
| `trust[route]` | Адресные действия близости, не общий рейтинг | Участие в последнем свидании и проверка финала |
| `boundaries` | Готовность Алисы просить, отказывать и слышать отказ | Условия романтического финала |
| `repairDebt` | Непогашенная цена избегания/нарушенного обещания | Романтический финал fail-closed при долге > 0 |
| `careerThesis` | Угол профессионального материала | Текст эпизода 12 и редакционное последствие |
| `flags` | Конкретные события: поддержанный план, маршрут, ремонт конфликта, тема материала, детали школы и западная бытовая сцена Эрика | Предпосылки веток, route-specific payoff и финальный доказательный след |
| `commitment` | Конкретный следующий шаг после поездки | Требуется для парного финала |
| `runId` | Идентификатор отдельного прохождения | Запрещает старому cloud response воскресить сброшенную игру |
| `runStartedAt` / `revision` / `updatedAt` | Версия и порядок изменений внутри прохождения | Сначала сравнивается прохождение, затем revision, а не номер эпизода |

Route lock в эпизоде 7 требует адресного флага поддержки и минимум одного более раннего route-specific события (`flagsAll` + `flagsAny`); иначе доступен независимый вариант. Общий `repair` больше не начисляет доверие всем героям. Каждый маршрут ремонтирует только свой конфликт (`<route>-conflict-repaired`) и имеет собственное последнее свидание. Явный repair уменьшает накопленный `repairDebt`; корректная защита приватности сама по себе долг не создаёт.

В маршруте Эрика после `ep8-eric` выбор приводит к одному из трёх наблюдаемых продолжений (`eric-plan-details`, `alice-work-shared`, `eric-quiet-kept`). После ремонта конфликта `ep9-eric-conflict` ведёт в пробный маршрут школы на Snæfellsnes: три способа участия выставляют `eric-workshop-shared`, `eric-workshop-questioned` или `eric-workshop-rested`, а вечерняя сцена выставляет `eric-kitchen-open` либо `eric-kitchen-paused`. Последнее свидание читает эти флаги через runtime-подстановку и не подменяет их общим текстом.

Сохранения schema 2/3 мигрируют в schema 4 в `src/main.js`: сохраняются узел, прогресс, доверие и флаги; отсутствующие поля получают безопасные значения и legacy run id. Новые локальные сохранения пишутся под `v4`, а cloud key намеренно остаётся прежним для совместимости. Reset создаёт новый `runId` и отправляет пустое начальное состояние в cloud; cloud state более старого прохождения игнорируется даже если он глубже по эпизоду.

Финал маршрута доступен только при: `routeIntent` совпадает с маршрутом; `trust[route] >= 3`; `boundaries >= 2`; `repairDebt === 0`; присутствуют route-specific repair и `concrete-plan`. `careerThesis` выбирает различимый редакционный результат (`people`, `place`, `choice`) и финальная реплика получает соответствующий consequence-text. Иначе доступен честный независимый финал, а не внезапная романтическая награда.
