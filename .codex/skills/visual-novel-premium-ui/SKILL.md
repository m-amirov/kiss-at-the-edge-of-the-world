# Visual Novel Premium UI

Использовать для изолированных UI-концепций и последующей выбранной реализации. Не заменяет `mobile-game-ux`, `game-accessibility`, `visual-quality-gate` или `web-game-playtest`; дополняет их художественной системой.

## Иерархия и композиция

- Сначала обеспечить читаемость лица, жеста и ключевого события; UI не перекрывает центральную safe-zone 60% CG.
- Выстроить три уровня: сцена/CG, драматургически важный текст, навигация и системные действия.
- Каждый вариант обязан иметь собственную композиционную логику, а не только другую палитру: меняются anchor панели, ритм сетки и способ перехода между состояниями.
- На 1920×900 сохранять cinematic breathing room; на 390×844 перестраивать интерфейс, а не масштабировать desktop.

## Типографика и дизайн-система

- Использовать локальные системные или уже поставляемые проектом шрифты; не подключать CDN.
- Display-шрифт — только для названия и коротких заголовков; основной текст — нейтральный, с межстрочным интервалом не менее 1.4.
- Ограничить систему двумя акцентными цветами и одним цветом интеракции; состояние не передавать только цветом.
- Закрепить токены цвета, spacing, радиуса, тени, focus-ring и motion duration в CSS `:root` концепции.

## Интеракция и motion

- Hover, focus-visible, pressed и selected должны быть различимы формой, контрастом и подписью.
- Анимации 160–360ms, только для появления, фокуса и смены сцены; чтение не блокировать.
- При `prefers-reduced-motion: reduce` отключать декоративные переходы и сохранять мгновенный доступ к состоянию.

## Доступность и mobile

- Интерактивная область не менее 44×44 CSS px; клавиатурный focus всегда видим.
- Контраст текста проверять на фактическом фоне, длинные русские строки — на 360×640.
- Portrait: выборы вертикальным стеком, системные действия в reachable-зоне большого пальца, CG с portrait-safe crop или letterbox.
- Landscape: не обрезать speaker/continue и не допускать горизонтального overflow; при узкой высоте сжимать панели, не лица.

## Acceptance

Перед выбором направления нужны реальные browser screenshots desktop 1920×900, 390×844, 360×640 и landscape, а также проверка клавиатуры, reduced motion, длинных choices и отсутствия overflow. Это UI-прототип, поэтому не меняет save, route, SDK или production runtime.
